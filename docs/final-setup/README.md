# Final setup: what is installed

The configuration chosen for the client after the pilot, as installed by this repository.
It is the [minimal setup](../minimal-setup.md) profile with path routing: five components on
one Docker host, every tool at `https://<host>/<tool>`, where `<host>` is the server's IP
(`HOST_ADDRESS` in `.env`; no DNS zone is involved).

## Installed tools

| Tool | Image (pinned in `versions.env`) | URL | Role | Data |
|---|---|---|---|---|
| Traefik | `traefik:v3.7` | `https://<host>/dashboard/` | TLS termination and reverse proxy, one certificate for the host, port 80 redirect | `${DATA_ROOT}/traefik` (certificate, dashboard login) |
| Gitea | `gitea/gitea:1.23` + `postgres:16-alpine` | `https://<host>/gitea`, SSH on 2222 | source control, pull requests, branch protection, webhooks to Jenkins | `${DATA_ROOT}/gitea` |
| Jenkins | `jenkins/jenkins:lts-jdk21` (controller image built locally with pinned plugins) + `tecnativa/docker-socket-proxy:0.3.0` | `https://<host>/jenkins` | CI/CD, configured by JCasC, zero executors, builds on ephemeral Docker agents | `${DATA_ROOT}/jenkins` |
| Jenkins agent image | `devsecops/jenkins-agent:local`, built from `jenkins/agent:jdk21` | runs per build | carries Trivy, Gitleaks, Syft, hadolint, Semgrep, Checkov and the Docker CLI | none (throwaway) |
| SonarQube Community Build | `sonarqube:community` + `postgres:16-alpine` | `https://<host>/sonarqube` | code quality and quality gate for PHP and TypeScript | `${DATA_ROOT}/sonarqube` |
| Nexus Repository CE | `sonatype/nexus3:3.79.1` | `https://<host>/nexus`, registry `<host>:5000` | npm and Composer proxies, hosted Docker registry | `${DATA_ROOT}/nexus` |

Scanner versions inside the agent image, from `versions.env`: Trivy 0.61.0, Gitleaks 8.24.2,
Syft 1.23.1, hadolint 2.12.0. Semgrep and Checkov are installed by pipx at build time and
currently float to the latest release (an open item, see below).

Two image tags float by design and should be reviewed before each rerun: `sonarqube:community`
tracks SonarQube's monthly Community Build, `jenkins/jenkins:lts-jdk21` tracks the Jenkins LTS
line. Pin them to a digest in `versions.env` when the client wants fully reproducible rebuilds.

## How it was installed

```bash
# first run, creates .env with these values and generated passwords
sudo INGRESS=traefik HOST_ADDRESS=<host> JENKINS_MAX_AGENTS=3 ./install.sh --only traefik,gitea,jenkins,sonarqube,nexus
# later runs read .env
sudo ./install.sh --only traefik,gitea,jenkins,sonarqube,nexus
```

Host: one dedicated server, 24 vCPU, 62 GB RAM, Debian, Docker Engine 29. With
`JENKINS_MAX_AGENTS=3` the budget is about 29 GB and 10 vCPU, so the host has headroom for
five agents or for the next components.

## Network exposure

| Port | Protocol | Serves |
|---|---|---|
| 80 | HTTP | redirect to 443 |
| 443 | HTTPS | `/gitea`, `/jenkins`, `/sonarqube`, `/nexus`, `/dashboard/` |
| 2222 | SSH | Git over SSH (Gitea) |
| 5000 | HTTPS | Nexus Docker registry connector |

The server has a public IP. These four ports must be restricted to the client's office and
VPN ranges in the provider firewall; nothing in this stack is meant to be reachable from the
internet. Ports 8200, 8083, 8090 and 8091 are published by Traefik for Vault, DefectDojo and
Dependency-Track and answer 502 until those components are installed; close them too for now.

## Certificate

Self-signed, generated by the installer for the host IP, valid ten years, served on every
TLS port, trusted by the host's Docker daemon. Developers import it once. Everything about
it, including replacement by a client CA certificate, is in [tls.md](../tls.md).

## Not installed, and why

| Component | Status | Reason |
|---|---|---|
| Keycloak (single sign-on) | deferred | one user list per tool is acceptable for the pilot team; add when the client connects its directory. Ready at `/keycloak`. |
| Vault (secrets) | deferred | pipeline secrets live in the Jenkins credential store for now. Will use port 8200. |
| DefectDojo (findings inbox) | deferred | scan reports stay on the Jenkins build page as archived artifacts. Will use port 8083. |
| Dependency-Track (SBOM tracking) | deferred | SBOMs are archived per build; no re-evaluation against new CVEs until this is added. Ports 8090 and 8091. |
| Prometheus, Grafana, Loki | deferred | the client monitors the host with its own tooling for now. Ready at `/grafana` and `/prometheus`. |
| Host scanner wrappers | not installed | operators have not asked to run scanners by hand on the host; `sudo ./install.sh --only scanners` adds them. |

Each one is added with `sudo ./install.sh --only <component>`; nothing already installed
changes.

## Open items

- Semgrep and Checkov in the agent image are not pinned (pipx installs the latest). Pin them
  in `stacks/jenkins/agent/Dockerfile` for reproducible builds.
- Build agents reach Gitea only through the public HTTPS URL, which the agent image does not
  trust yet. Use SSH clone URLs in the Jenkins Gitea server configuration, or bake the
  certificate into the agent image ([tls.md](../tls.md), "Tools calling each other").
- Firewall rules on the provider side, see above.
- Post-install checklist in the repository README: Nexus repositories and the `ci` user,
  SonarQube token and webhook, Jenkins Gitea server entry and organisation folder, developer
  pre-commit hook, nightly snapshot of `DATA_ROOT`.

The reasoning behind each choice is in [decisions.md](decisions.md).
