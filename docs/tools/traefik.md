# Traefik

Reverse proxy and TLS termination for every web interface in the stack.

## Role in the chain

Every tool is reached as `https://<name>.<DOMAIN>`. Traefik watches the Docker socket, reads
the `traefik.*` labels on each container, and builds the routes itself. No tool exposes a host
port except Traefik (80, 443) and Gitea SSH.

## Deployment

| Item | Value |
|---|---|
| Stack | `stacks/traefik/docker-compose.yml`, installed by `scripts/10-traefik.sh` |
| Image | `TRAEFIK_IMAGE` in `versions.env` |
| Static config | `${DATA_ROOT}/traefik/traefik.yml`, generated by the script |
| Data | `${DATA_ROOT}/traefik/letsencrypt/acme.json` (certificates), `usersfile` (dashboard login) |
| URL | `https://traefik.<DOMAIN>/dashboard/`, basic auth from `TRAEFIK_DASHBOARD_USER` and `TRAEFIK_DASHBOARD_PASSWORD` |
| Metrics | `:8082/metrics`, scraped by Prometheus |
| Budget | 0.5 vCPU, 128 MB |

## TLS modes

Private network (default): `CERT_RESOLVER` is empty, Traefik serves its built-in self-signed
certificate. Browsers warn, `curl` needs `-k`, and tools that call each other (Jenkins to
SonarQube, Gitea webhooks to Jenkins) need the certificate trusted or verification disabled.
This is acceptable for a pilot, not for production.

Internal CA (recommended for the client): obtain a wildcard certificate for `*.<DOMAIN>` from
the client's CA, put the certificate and key under `${DATA_ROOT}/traefik/certs/`, and add a
dynamic file provider. In `traefik.yml`:

```yaml
providers:
  file:
    filename: /etc/traefik/dynamic.yml
```

and in `${DATA_ROOT}/traefik/dynamic.yml`:

```yaml
tls:
  certificates:
    - certFile: /certs/wildcard.crt
      keyFile: /certs/wildcard.key
  stores:
    default:
      defaultCertificate:
        certFile: /certs/wildcard.crt
        keyFile: /certs/wildcard.key
```

Mount both paths in the compose file and restart the stack. Also add the CA certificate to the
Jenkins agent image and to each JVM truststore (SonarQube, Nexus, Dependency-Track) so that
service-to-service calls validate.

Public DNS: set `CERT_RESOLVER=le` and `ACME_EMAIL`, open port 80 from the internet, rerun
`scripts/10-traefik.sh`. Let's Encrypt issues one certificate per hostname automatically.

## Operations

- Logs: `docker logs traefik`. Access logs are on, one line per request.
- Add a service: give the container `traefik.enable=true`, a router rule, `entrypoints=websecure`,
  `tls=true` and a `loadbalancer.server.port`. Copy the block from any stack.
- Upgrade: bump `TRAEFIK_IMAGE`, run `sudo ./install.sh --only traefik`. Static config is
  regenerated on each run, so make lasting edits in `scripts/10-traefik.sh`.
- Backup: `acme.json` and `usersfile`. Everything else is regenerated.

## Security notes

- The Docker socket is mounted read-only. Traefik still sees every container's labels and
  environment; treat the Traefik host as part of the platform's trust boundary.
- Prometheus is published behind the same basic auth middleware as the dashboard because it has
  no login of its own.
- Rate limiting and IP allow-lists are one middleware label away when the client wants them.
